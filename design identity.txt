# WENODES — Brand, Design & Interaction System

## 01 — Brand Positioning

**WENODES is a creative technology collective working at the intersection of art, technology, interaction, audiovisual systems, and experimental digital experiences.**

The brand should not feel like a conventional:

* creative agency
* software company
* production studio
* portfolio website

Instead, it should feel like a **living technological environment**.

The website is therefore not simply a place that displays projects. It is itself an example of the way WENODES thinks:

> **Technology is not only a tool for creating experiences. Technology can become the experience.**

The identity combines:

**creative experimentation + engineering precision + audiovisual culture + interactive systems.**

---

# 02 — Core Brand Concept

### "Living Systems"

This is the central conceptual direction.

WENODES creates systems that:

* respond
* react
* evolve
* transform
* communicate
* behave according to inputs

This concept should appear both in the **content** and in the **interface behavior**.

A page shouldn't simply:

```text
display → wait
```

It should:

```text
observe → react → transform → settle
```

That distinction is important.

The website should feel like something that is **running**, rather than something that is merely being viewed.

---

# 03 — Visual Personality

The visual personality is:

### Experimental

The design should feel like a laboratory for new ideas.

### Technical

Interfaces contain system information, numbers, categories, states and metadata.

### Minimal

There is very little unnecessary decoration.

### Atmospheric

Dark backgrounds, grain, particles and subtle motion create depth.

### Editorial

Large typography and carefully controlled whitespace create a strong art-direction layer.

### Cinematic

Images, transitions and pacing should feel closer to an audiovisual installation than a standard portfolio.

### Intelligent

The interface should feel deliberately engineered rather than decorated.

### Slightly mysterious

Not everything needs to be explained immediately.

### Confident

The design doesn't need excessive marketing language or visual noise to establish credibility.

# 04 — Color System

The foundation is a **monochromatic dark environment**.

### Background

```css

#0a0a0a
```

These create different levels of depth rather than relying on multiple colors.

### Primary text

```css

#f4f4f0
```

Warm whites are preferable to pure `#fff`.

This keeps the interface cinematic and less sterile.

### Secondary information

```css
#888
#666
#555
```

### Borders

```css
rgba(232,230,227,0.08)
rgba(232,230,227,0.12)
rgba(232,230,227,0.25)
rgba(232,230,227,0.6)
```

### Color philosophy

The interface itself remains mostly monochrome.

**The projects provide the color.**

That is important because it allows project imagery, installations, videos and generative work to become the visual climax.

# 09 — Oversized Typography

Large typography is one of the main visual components.

Instead of:

```text

```


Instead of:

```text

```


# 12 — Interactive Philosophy

Interaction should not exist simply because "animation looks cool."

Every interaction should communicate **system behavior**.

The ideal interaction model is:

```text
INPUT
 ↓
SYSTEM RESPONSE
 ↓
TRANSFORMATION
 ↓
SETTLE
```

Examples:

### Mouse

```text
mouse movement
      ↓
particle field disturbance
      ↓
particles respond
```

### Hover

```text
hover project
      ↓
image darkens
      ↓
image scales
      ↓
metadata appears
      ↓
gallery activates
```

### Scroll

```text
scroll velocity
      ↓
elements react
      ↓
movement increases
      ↓
system settles
```

This makes interaction feel intentional rather than decorative.

---

# 13 — Motion Language

Motion should generally be:

* smooth
* delayed
* layered
* responsive
* slightly physical
* never overly bouncy

Good motion:

```text
opacity
transform
scale
blur
image displacement
particle movement
stagger
```

Avoid excessive:

```text
spin
bounce
elastic UI
random transitions
```

The overall motion language should feel closer to **physics and audiovisual systems**.

# 17 — Gallery Interaction

Gallery behavior should feel continuous.

Avoid:

```text

→ jump
→ image 2
→ jump
→ cover
```

Instead:

```text

→ image 2
→ image 3
→ image 4
```

with controlled fading/crossfading.

The gallery should activate after a deliberate hover delay rather than immediately.

This prevents accidental interaction while browsing.

# 27 — Responsive Behavior

Mobile should not simply be a smaller desktop.

The system should adapt.

Desktop:

```text
large typography
large whitespace
multi-column layouts
particle interaction
hover galleries
```

Mobile:

```text
single-column content
touch-friendly interactions
swipe galleries
reduced particle density
simplified hover-dependent information
```

Because there is no real hover on touch devices, important information should never depend exclusively on `:hover`.

# 6. Motion language

Motion is a major part of the WENODES identity.

The principle is:

> **The interface behaves like a system.**

Not:

> "Everything has a flashy animation."

Animations should feel **physical, responsive and computational**.

### Existing visual language

* particle background
* grain
* pixel logo
* image transitions
* card entrance animations
* hover image scaling
* gallery cycling
* fade transitions
* staggered elements

### Expand this with

**Cursor interaction**

Particles react to cursor position.

```text
cursor → field disturbance → particles respond
```

**Magnetic buttons**

Buttons subtly move toward the cursor.

**Text reveal**

Large headlines reveal line-by-line or character-by-character.

**Image displacement**

Images can subtly distort on hover rather than simply scaling.

**Scroll velocity**

Fast scrolling produces slightly stronger motion; slow scrolling settles the system.

**Micro-interactions**

Buttons, metadata, counters and indicators should respond to interaction.
